## 1. Google Identity Services (GIS)

### 1a. "Sign in with Google" ID-token flow

- **FedCM status.** GIS One Tap runs on FedCM; the `use_fedcm_for_prompt` option is now listed as *"deprecated and will be ignored if used"* ([JS reference](https://developers.google.com/identity/gsi/web/reference/js-reference)). FedCM needs Chrome 117+; the GIS FedCM beta launched Aug 2023; Chrome M121 changed auto-sign-in UX ([FedCM migration](https://developers.google.com/identity/gsi/web/guides/fedcm-migration)). The "mandatory by **August 2025**" deadline applies to the *legacy* `gapi.auth2`/`platform.js` library, not GIS ([gsi-with-fedcm](https://developers.google.com/identity/sign-in/web/gsi-with-fedcm)). No further 2026 deadline is published. ⚠️ `use_fedcm_for_button` (FedCM button UX, Chrome M125+/Android M128+) still exists and defaults to `false`.
- **Options.** `auto_select` default `false`; `cancel_on_tap_outside` default `true`; `context`, `hd`, `nonce`, `ux_mode`, `itp_support` as documented ([JS reference](https://developers.google.com/identity/gsi/web/reference/js-reference)).
- **`prompt()` notifications under FedCM.** *"the google.accounts.id.prompt callback no longer returns any display moment notification"*: `isDisplayMoment/isDisplayed/isNotDisplayed/getNotDisplayedReason` are "Not supported"; `isSkippedMoment/getSkippedReason` are "partially supported" (no `user_cancel`); `isDismissedMoment/getDismissedReason` (`credential_returned`, `cancel_called`, `flow_restarted`) are fully supported ([migration](https://developers.google.com/identity/gsi/web/guides/fedcm-migration), [reference](https://developers.google.com/identity/gsi/web/reference/js-reference)). Practical handling: treat anything that is not `credential_returned` as "no sign-in; show the button"; never branch on display reasons. Call `google.accounts.id.disableAutoSelect()` on sign-out to avoid the auto-select "dead loop".
- **ID token contents.** Claims: `iss` (`https://accounts.google.com`), `aud`, `sub` (*"unique among all Google Accounts and never reused"*), `azp`, `iat`, `exp`, `email`, `email_verified`, `name`, `given_name`, `family_name`, `picture`, `hd` (Workspace domain), `nonce`, `locale`, `at_hash` ([OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)). *"User ID tokens are valid for one hour, and can't be revoked"* ([Token types](https://docs.cloud.google.com/docs/authentication/token-types)).
- **Validation in a client-only app.** Google: *"You need to validate all ID tokens on your server unless you know that they came directly from Google"*; *"strongly recommended that you Verify the Google ID token on your server"* ([handle responses](https://developers.google.com/identity/gsi/web/guides/handle-credential-responses-js-functions)). With no backend, decode the base64url payload for display only; the only trust you have is that the GIS library delivered it over HTTPS. Still check `aud` == your client ID, `iss`, `exp`, and use **`sub`** (not email) as the user key. `https://oauth2.googleapis.com/tokeninfo?id_token=…` exists but is *"useful for debugging"*, may be throttled, not for production ([OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)).

### 1b. OAuth 2.0 token model (`initTokenClient` / `requestAccessToken`)

- **`prompt`.** Default `'select_account'`; `''` = *"The user will be prompted only the first time your app requests access. Cannot be specified with other values"*; `'none'` must be alone; `'consent'`, `'select_account'` ([OAuth JS reference](https://developers.google.com/identity/oauth2/web/reference/js-reference)). ⚠️ Whether a popup still *flashes* for returning users with `prompt: ''` is **not documented**; the library always opens a popup (hence `popup_failed_to_open`/`popup_closed` errors), and community reports describe a brief auto-closing window. Treat as expected.
- **`error_callback` types.** `popup_failed_to_open` ("The popup window is failed to open"), `popup_closed` ("closed before an OAuth response is returned"), `unknown` ("Placeholder for other errors") — Google says to check `type` since more may be added ([reference](https://developers.google.com/identity/oauth2/web/reference/js-reference), [errors](https://developers.google.com/identity/oauth2/web/guides/error)).
- **Scopes/params.** `include_granted_scopes` *"defaults to true"* (incremental auth); `login_hint` = email or `sub`; `hd`; `state` (discouraged); `enable_granular_consent`/`enable_serial_consent` deprecated/no effect. ⚠️ There is **no `hint` field** in the current `TokenClientConfig`/`OverridableTokenClientConfig`; only `login_hint`. `hasGrantedAllScopes(tokenResponse, scope, …)` / `hasGrantedAnyScope` ([reference](https://developers.google.com/identity/oauth2/web/reference/js-reference)).
- **Lifetime / refresh.** `expires_in: 3600` in the sample response ([implicit flow](https://developers.google.com/identity/protocols/oauth2/javascript-implicit-flow)); *"By design, access tokens have a short lifetime"*, no per-user refresh tokens, re-call `requestAccessToken()` *"from a user-driven event such as a button press"* ([token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)).
- **Revoke.** `google.accounts.oauth2.revoke(accessToken, done)` *"revokes all of the scopes that the user granted to the app"* ([reference](https://developers.google.com/identity/oauth2/web/reference/js-reference)).
- **Authorized JavaScript origins.** Must be HTTPS (localhost exempt), no raw IPs (localhost exempt), no wildcards, no path/query/fragment, TLD on the public-suffix list ([implicit flow rules](https://developers.google.com/identity/protocols/oauth2/javascript-implicit-flow)); for dev *"add both `http://localhost` and `http://localhost:<port_number>`"*; One Tap needs HTTPS ([client ID guide](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)). ⚠️ www vs apex: not stated explicitly, but an origin is scheme+host(+port), so add `https://camplist.guide` **and** `https://www.camplist.guide` if both serve the app.

### 1c. Drive API v3 with `drive.file`

- **Visibility & classification.** `drive.file`: *"Create new Drive files, or modify existing files, that you open with an app or that the user shares with an app while using the Google Picker API or the app's file picker"*; listed as **Non-sensitive**, "recommended" ([Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)). `files.list` therefore only returns files the app created or the user picked.
- **Verification.** *"If your app utilizes only non-sensitive scopes, it is not mandatory for your app to complete the app verification process"* ([verification](https://support.google.com/cloud/answer/9110914)). The "unverified app" screen and the cap of *"100 new users in total, after the app presents the unverified app screen"* apply when a request includes **unapproved sensitive/restricted** scopes; **Testing** status is limited to 100 listed test users, **In production** is open to any Google Account ([audience](https://support.google.com/cloud/answer/15549945), [unverified apps](https://support.google.com/cloud/answer/7454865)). Brand verification is still needed to show name/logo on the consent screen.
- **Create folder.** `POST https://www.googleapis.com/drive/v3/files` body `{"name":"CampList","mimeType":"application/vnd.google-apps.folder"}`; put children via `"parents":["FOLDER_ID"]` (one parent only) ([folders](https://developers.google.com/workspace/drive/api/guides/folder)).
- **Create/update JSON (multipart, ≤5 MB).** Create: `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart`; update: `PATCH https://www.googleapis.com/upload/drive/v3/files/{fileId}?uploadType=multipart` (or `uploadType=media` with a raw body) ([uploads](https://developers.google.com/workspace/drive/api/guides/manage-uploads)):

  ```js
  const B = 'camplist_boundary';
  const body = `--${B}\r\nContent-Type: application/json; charset=UTF-8\r\n\r\n` +
    JSON.stringify({ name: 'trip.json', mimeType: 'application/json', parents: [folderId],
                     appProperties: { camplist: '1', tripId } }) +
    `\r\n--${B}\r\nContent-Type: application/json\r\n\r\n` + JSON.stringify(data) + `\r\n--${B}--`;
  await fetch('https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart&fields=id,name,modifiedTime',
    { method: 'POST', headers: { Authorization: `Bearer ${token}`,
      'Content-Type': `multipart/related; boundary=${B}` }, body });
  ```
- **List in folder.** `GET https://www.googleapis.com/drive/v3/files?q=<enc>&fields=nextPageToken,files(id,name,modifiedTime,appProperties)&spaces=drive&pageSize=100` with `q` = `'FOLDER_ID' in parents and trashed = false and mimeType='application/json'`; app-property filter `appProperties has { key='tripId' and value='…' }` ([search](https://developers.google.com/workspace/drive/api/guides/search-files)).
- **`appProperties`.** Private to the app (OAuth client); limits: 100 custom properties/file total, 30 public, 30 private per app, **124 bytes per property (key+value, UTF-8)** ([properties](https://developers.google.com/workspace/drive/api/guides/properties)).

### 1d. Google Picker (2026)

- Still requires an **API key** (`setDeveloperKey`), an **OAuth token** (`setOAuthToken`), and `setAppId(projectNumber)` — `setAppId` is *"required for the `https://www.googleapis.com/auth/drive.file` scope"*, parameter is *"The Cloud project number"* ([setAppId](https://developers.google.com/workspace/drive/picker/reference/picker.pickerbuilder.setappid), [web picker](https://developers.google.com/workspace/drive/picker/guides/web-picker)). Files picked become accessible under `drive.file`.
- Load `https://apis.google.com/js/api.js` → `gapi.load('picker', cb)`. `new google.picker.DocsView(google.picker.ViewId.FOLDERS)` with `setIncludeFolders(true)`, `setSelectFolderEnabled(true)`, `setMimeTypes`, `setParent`, `setOwnedByMe`; `ViewId.FOLDERS` = "Google Drive Folders" ([DocsView](https://developers.google.com/workspace/drive/picker/reference/picker.docsview), [ViewId](https://developers.google.com/workspace/drive/picker/reference/picker.viewid)).
- Google: the Picker *"renders in an iframe hosted on `docs.google.com`"* — an API-key website restriction must include `https://docs.google.com/*` or you get "API developer key is invalid" ([web picker](https://developers.google.com/workspace/drive/picker/guides/web-picker)). ⚠️ No official CSP or third-party-cookie guidance exists; community reports say the Picker can fail when cookies are blocked.

### 1e. COOP

- Google: *"When FedCM is disabled, set the COOP header to `same-origin` and include `same-origin-allow-popups`"*; *"Failing to set the proper header breaks communication between windows, leading to a blank pop-up window"* ([client ID guide](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)). The OAuth token popup checks `window.closed`; with `COOP: same-origin` Chrome logs "Cross-Origin-Opener-Policy policy would block the window.closed call" (⚠️ community: [Auth0 forum](https://community.auth0.com/t/loginwithpopup-cross-origin-opener-policy-policy-would-block-the-window-closed-call/191909)). **Rule: do not send `COOP: same-origin`; either omit COOP or use `same-origin-allow-popups`.**

## 2. Microsoft identity platform (`@azure/msal-browser`)

- **Version.** npm `latest` = **5.25.0** (2026-10-06); `lts` tag = 4.30.0 (npm registry, checked directly). Microsoft's own CDN is *"fully deprecated as of @azure/msal-browser@3.0.0"* ([README](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/README.md), [cdn-usage](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/docs/cdn-usage.md)). Verified working (HTTP 200) third-party CDN forms:
  - ESM: `import { PublicClientApplication } from "https://cdn.jsdelivr.net/npm/@azure/msal-browser@5/+esm"` (also `https://esm.sh/@azure/msal-browser@5`).
  - Global (UMD, exposes `window.msal`): `https://cdn.jsdelivr.net/npm/@azure/msal-browser@5.25.0/lib/msal-browser.min.js` or `https://unpkg.com/@azure/msal-browser@5/lib/msal-browser.min.js`.
  - **cdnjs does not host it** (404 for `msal-browser` and `msal`).
- **Flow.** Auth-code + **PKCE** only; *"does NOT support the implicit flow"* ([README](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/README.md)). Entra requires `code_challenge`/`S256` for SPAs and a redirect URI of type **`spa`** (CORS-enabled token redemption); otherwise you get "cross-origin token redemption is permitted only for the 'Single-Page Application' client-type" ([auth code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)).
- **v5 breaking change — redirect bridge.** *"Microsoft Entra ID now has Cross-Origin-Opener-Policy (COOP) enabled by default"*; *"All authentication flows (acquireTokenSilent(), ssoSilent(), loginPopup(), loginRedirect(), and logoutPopup()) now use the redirect bridge"* ([v4→v5 migration](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/docs/v4-migration.md)). `redirectUri` must point to a dedicated page that calls `broadcastResponseToMainFrame()` from `@azure/msal-browser/redirect-bridge`, has a static `<title>`, must **not** be served with COOP headers, must be served with `Cache-Control: no-store`, and the bridge script must be bundled/served with your app, *not* from a third-party CDN ([redirect-bridge.md](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/docs/redirect-bridge.md)). For a no-bundler site: copy `lib/redirect-bridge/msal-redirect-bridge.min.js` from the npm package into `public/`, and set the header via Replit `responseHeaders` (see §4). v5 also removed `storeAuthStateInCookie`, `logout()`, `getAccountByUsername()` etc.
- **Popup vs redirect.** *"Popup flows can be unreliable in Safari and mobile browsers"*; redirect is *"the most reliable interaction type across browsers"* but needs `await handleRedirectPromise()` on load ([initialization.md](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/docs/initialization.md)).
- **`acquireTokenSilent` / 24 h.** Cache → refresh token → hidden iframe ([SPA acquire token](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-spa-acquire-token)). *"Refresh tokens sent to a redirect URI registered as `spa` expire after 24 hours … apps must be prepared to rerun the authorization code flow using an interactive authentication … every 24 hours. Users don't have to enter their credentials and usually don't even see any related user experience"*; must be top-level because of third-party-cookie blocking ([refresh tokens](https://learn.microsoft.com/en-us/entra/identity-platform/refresh-tokens)). Catch `InteractionRequiredAuthError` → `acquireTokenPopup/Redirect`.
- **Cache.** Default `sessionStorage`; `localStorage` is shared across tabs; since v4, localStorage artifacts are AES-GCM encrypted with a key in the session cookie `msal.cache.encryption` unless the user picks "Keep me signed in" — *"to reduce the persistence of auth artifacts, not to provide additional security"* ([caching.md](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/dev/lib/msal-browser/docs/caching.md)).
- **App registration.** Supported account types: "Any Entra ID Tenant + Personal Microsoft accounts" (older label: "Accounts in any organizational directory … and personal Microsoft accounts"); platform **Single-page application** ([register app](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), [SPA config](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-spa-app-configuration)).
- **`Files.ReadWrite.AppFolder`.** Delegated, *"Have full access to the application's folder (preview)"*, **AdminConsentRequired: No**, *"available for consent in personal Microsoft accounts"* ([Graph permissions](https://learn.microsoft.com/en-us/graph/permissions-reference)). Graph concept doc: *"App folder works across OneDrive for work or school and OneDrive for home"* ([app folder](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder)). ⚠️ The older OneDrive doc still says the scope is *"only valid for personal accounts"* ([OneDrive perms](https://learn.microsoft.com/en-us/onedrive/developer/rest-api/concepts/permissions_reference)) — contradictory; test with a work account.
- **Endpoints** (folder auto-created at `Apps/{app name}`; `approot` is case-sensitive): `GET /me/drive/special/approot`, `GET /me/drive/special/approot/children`, `PUT /me/drive/special/approot:/{filename}:/content` (body = bytes, `Content-Type` e.g. `application/json`; returns `driveItem`, 201/200), `GET /me/drive/special/approot:/{filename}:/content` ([app folder](https://learn.microsoft.com/en-us/onedrive/developer/rest-api/concepts/special-folders-appfolder)). Simple upload now documented as *"files up to 250 MB"* (the old 4 MB figure no longer appears) ([put content](https://learn.microsoft.com/en-us/graph/api/driveitem-put-content)). **Browser caveat:** `GET …/content` answers `302` to a pre-authenticated URL, and a 302 *"is explicitly prohibited when a CORS preflight is required"* — instead `GET …?select=id,@microsoft.graph.downloadUrl` and fetch that URL **without** an Authorization header ([get content](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content)).
- **ID token claims.** `oid` immutable GUID, same across apps; `sub` pairwise per app; `tid` (`9188040d-6c67-4c5b-b112-36a304b66dad` = personal accounts); `preferred_username` mutable, *"can't be used to make authorization decisions"*; `email` *"isn't guaranteed to be correct and is mutable … Never use it for authorization"* ([ID token claims](https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference)). Optional claim **`xms_edov`** = *"whether the user's email domain owner has been verified"*; true only for tenant-verified domains, MSA, Google, or OTP-verified emails; requires the `email` claim ([optional claims](https://learn.microsoft.com/en-us/entra/identity-platform/optional-claims-reference)). For cross-provider account linking: key on Google `sub` and Microsoft `oid`+`tid`, and only auto-merge on email when Google `email_verified` and Microsoft `xms_edov` are true.

## 3. WorkOS AuthKit for a backend-less SPA

- **Yes, PKCE client-only is supported** via `@workos-inc/authkit-js` (v0.20.4) / `authkit-react`. From the SDK source (npm tarball): S256 PKCE, code verifier in `sessionStorage`, browser POSTs to `/user_management/authenticate` with `code_verifier`; access token kept in memory; refresh token in an **HttpOnly cookie** (`credentials: "include"`) when `devMode` is false, else **localStorage** (`devMode` defaults to `true` on `localhost`/`127.0.0.1`). Docs: *"If you have not set up a custom authentication domain in WorkOS, set `devMode={true}` … This will keep the refresh token in local storage instead of a secure, HTTP-only cookie"*; *"the client-only integration cannot be nested inside an iframe"* ([client-only](https://workos.com/docs/authkit/client-only)). Production therefore needs a **custom auth domain** (`apiHostname`, e.g. `auth.camplist.guide`) so the cookie is first-party; defaults: access token 5 min, refresh token 7 days, rotation on use ([blog](https://workos.com/blog/session-management-for-frontend-apps-with-authkit)).
- **Pricing.** *"First 1M MAUs"* free, then *"$2,500/mo"* per additional 1M; **custom domain $99/mo** ([pricing](https://workos.com/pricing)).
- **Providers.** Google, Microsoft, GitHub, Apple, GitLab, LinkedIn, Slack (+ Bitbucket, Discord, Salesforce, Vercel, Xero in the SDK enum) ([social login](https://workos.com/docs/authkit/social-login)).
- **Provider tokens for Drive/OneDrive.** Custom OAuth scopes exist for Google/Microsoft/GitHub/GitLab/Xero and the **server-side** Authenticate API returns `oauth_tokens {provider, access_token, refresh_token, expires_at, scopes}` ([API ref](https://workos.com/docs/reference/user-management/authentication)). But `authkit-js`'s `AuthenticationResponse` type has only `user, accessToken, refreshToken, authenticationMethod, organizationId, impersonator` — **the client SDK does not surface provider tokens**; ⚠️ whether the API even returns them to public (PKCE) clients is unverified. Conclusion: your belief is correct for practical purposes — Drive/OneDrive still require GIS/MSAL directly.
- **Identity linking.** Uses *"the email address as the unique identifier and access to the email inbox as the source of truth"*; a new credential (e.g. Google OAuth) is attached to the existing user only if WorkOS can verify inbox access; unverified = *"security risk"* ([identity linking](https://workos.com/docs/authkit/identity-linking)).
- **Comparison.** WorkOS: hosted UI, MFA, email-linking, free ≤1M MAU — but +$99/mo for the custom domain you need, a second sign-in step for Drive/OneDrive authorization anyway, and a third-party dependency. Direct GIS + MSAL: $0, tokens land directly in the page, but you own linking logic (Google `sub` ↔ Microsoft `oid`, email only when `email_verified`/`xms_edov`), MSAL v5 bridge page, and two SDKs. For an app whose only server-side need is cloud-file sync, direct GIS + MSAL is the smaller system.

## 4. Replit Static Deployments

- **What/config.** *"Static Deployments host your app's files … There is no backend server"*; configuration = *"the public directory to serve and an optional build command"*; not compatible with Agent-built apps ([static deployments](https://docs.replit.com/cloud-services/deployments/static-deployments)). The official `.replit` reference documents only `run`, `build`, `ignorePorts` under `[deployment]` ([configuring-repl](https://docs.replit.com/replit-workspace/configuring-repl)). ⚠️ `deploymentTarget = "static"` and `publicDir` are not shown in official docs; third-party guides consistently use **`publicDir = "dist"` (no leading slash)** with `build = ["sh", "-c", "npm ci && npm run build"]` ([example](https://www.rapidevelopers.com/md/replit-tutorial/how-to-deploy-a-static-site-using-replit-s-hosting-features)). Safest: set "Public directory = `public`" in the Publishing UI and let Replit write `.replit`.
- **Headers / rewrites — your belief is wrong: custom headers ARE supported.** `[[deployment.responseHeaders]]` with `path = "/*"`, `name`, `value`; reserved (non-configurable): Accept-Ranges, Age, Allow, Alt-Svc, Connection, Content-Encoding, Content-Length, Content-Range, Date, Location, Server, Set-Cookie, Trailer, Transfer-Encoding, Upgrade — so `Content-Security-Policy`, `X-Frame-Options`, `Cross-Origin-Opener-Policy`, `Cache-Control` are allowed. `[[deployment.rewrites]]` `from="/*"` `to="/index.html"` for SPA fallback (existing files win); custom 404 pages supported ([advanced static](https://docs.replit.com/features/deployment-customization/static-deployments-advanced)). ⚠️ The overview mentions "redirects" but the advanced page has no redirects section/TOML.
- **Custom domains.** Supported for Static ([static deployments ref](https://docs.replit.com/references/publishing/static-deployments)); add `A` + `TXT` records; *"Linking `hat-tip.cc` does not automatically serve `www.hat-tip.cc`"* — add www as a separate entry; TLS auto-issued/renewed via DNS validation (keep the TXT record) ([custom domains](https://docs.replit.com/cloud-services/deployments/custom-domains)).
- **Pricing (post-Aug-1-2026 cut).** Static: hosting **Free**, outbound **$0.05/GiB**. Autoscale: compute **$0.60 per million compute units**, **$0.40 per million requests**, base fee **$2.00/mo** on the pricing table ([deployment pricing](https://docs.replit.com/billing/deployment-pricing)) ⚠️ vs *"$1 / mo (unchanged)"* on the update notice ([Aug 2026 update](https://docs.replit.com/billing/aug-cloud-billing-updates)). Reserved VM $15–$130/mo. PostgreSQL: **$0.16 per compute hour**, storage **$0.35/GiB-month** (was $1.50). App/Object Storage (GCS-backed): **$0.015/GiB-month**, **$0.05/GiB** egress, $0.0004 / $0.005 per thousand basic/advanced ops ([object storage billing](https://docs.replit.com/billing/object-storage-billing)). Plans: Core **$20/mo** ($18/mo annual), Pro $100/mo ($90 annual) ([pricing](https://replit.com/pricing)); Core includes a 100 GiB outbound-transfer allowance ([usage billing](https://docs.replit.com/billing/about-usage-based-billing)).

## 5. CSP via `<meta http-equiv="Content-Security-Policy">`

- **Ignored in meta:** `frame-ancestors`, `report-uri`, `sandbox` (*"Neither are the report-uri, frame-ancestors, and sandbox directives"*), and `report-to`; *"policies in meta elements are not applied to content which precedes them"* → put it first in `<head>` ([CSP3 §meta](https://www.w3.org/TR/CSP3/#meta-element)). MDN: meta *"does not support all CSP features"* and a Report-Only policy *"cannot be delivered in a `<meta>` element"* ([MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP)). Since Replit lets you set real headers (§4), prefer the header for `frame-ancestors`.
- **Sources per vendor** (official unless marked):
  - GIS: `script-src https://accounts.google.com/gsi/client`; `frame-src https://accounts.google.com/gsi/`; `connect-src https://accounts.google.com/gsi/`; `style-src https://accounts.google.com/gsi/style` ([Google](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)).
  - Maps JS + Places (Google's allowlist CSP): `script-src 'self' 'unsafe-inline' 'unsafe-eval' https://*.googleapis.com https://*.gstatic.com *.google.com https://*.ggpht.com *.googleusercontent.com blob:`; `img-src 'self' https://*.googleapis.com https://*.gstatic.com *.google.com *.googleusercontent.com data:`; `frame-src *.google.com`; `connect-src 'self' https://*.googleapis.com *.google.com https://*.gstatic.com data: blob:`; `font-src https://fonts.gstatic.com`; `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com`; `worker-src blob:` ([Maps CSP](https://developers.google.com/maps/documentation/javascript/content-security-policy)). ⚠️ Narrowing to `maps.googleapis.com`/`maps.gstatic.com` is not what Google publishes.
  - Picker: `script-src https://apis.google.com`, `frame-src https://docs.google.com` (Google documents the docs.google.com iframe; ⚠️ no official CSP list).
  - Drive: `connect-src https://www.googleapis.com`.
  - MSAL/Entra (⚠️ derived from how MSAL works): `connect-src https://login.microsoftonline.com` (token POST), `frame-src https://login.microsoftonline.com` (silent iframe); popups are not governed by `frame-src`.
  - Graph: `connect-src https://graph.microsoft.com`; downloads via `@microsoft.graph.downloadUrl` hit other hosts (e.g. `*.files.1drv.com`, `*.sharepoint.com`) — ⚠️ allow or proxy accordingly.
  - Adobe Fonts/Typekit: `script-src use.typekit.net` (JS embed), `style-src 'unsafe-inline' use.typekit.net`, `img-src p.typekit.net` (usage beacon), optional `connect-src performance.typekit.net` ([Adobe](https://helpx.adobe.com/fonts/web/web-design-and-development/content-security-policy.html) — ⚠️ page returned 403 to fetch; text taken from search snippets of that page); add `font-src use.typekit.net`.
  - CDNs: `script-src https://cdn.jsdelivr.net https://cdnjs.cloudflare.com` (msal-browser is on jsDelivr/unpkg only).
